How it works

A typical backup keeps one full copy and then saves only what changed each day. The full copy and every daily change are shrunk by compression and deduplication. A buffer is added so the repository does not fill up as data grows.

full = data ÷ ratio daily changes = data × change% × (restore points − 1) ÷ ratio total = (full + daily changes) × (1 + buffer%)

This is a planning estimate. Backup products differ: some make periodic new full copies, some deduplicate across machines. If you also keep an offsite copy with the same retention, plan roughly the same space again at the offsite location.

Examples

8 TB file and database servers

8 TB of data, 3% daily change, 30 restore points, 1.5 ratio, 20% buffer. Full copy = 8 ÷ 1.5 = 5.33 TB. Daily changes = 8 × 0.03 × 29 ÷ 1.5 = 4.64 TB. Total = (5.33 + 4.64) × 1.2 = 11.97 TB.

2 TB small office

2 TB of data, 5% daily change, 14 restore points, 2:1 ratio, 25% buffer. Full copy = 1 TB. Daily changes = 2 × 0.05 × 13 ÷ 2 = 0.65 TB. Total = 1.65 × 1.25 = 2.06 TB.

FAQ

How do I find my daily change rate?

Look at the size of recent incremental backups in your backup software and divide by the total data size. File servers often change less than 3% a day; busy databases and mail servers change more.

Why is my disk smaller than the TB on the box?

Drive makers count 1 TB as 1,000,000,000,000 bytes. Windows counts in TiB (1,099,511,627,776 bytes) but labels it "TB". That is why the TiB figure above is lower.

Is RAID a backup?

No. RAID keeps a server running when a disk fails, but it copies mistakes, deletions and ransomware instantly. You still need separate backups, ideally including one offsite.
